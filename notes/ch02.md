# Chapter 2: Variables and Basic Types

Every commonly used programming language has a set of shared syntactic features. The most basic ones include:

- Built-in types such as integers and characters
- Variables, used to give names to objects
- Expressions and statements, used to manipulate the actual values of those data types
- Control structures such as `if` and `while`, used to conditionally execute statements or repeat them
- Functions, used to define units of computation that can be called when needed

Most programming languages extend these basic features in two additional ways:

- User-defined data types, which extend the language
- Library functions, which package useful functionality

### Basic Built-in Types

**Fundamental arithmetic types**:

| Type | Meaning | Minimum Size |
|---|---|---|
| `bool` | Boolean type | 8 bits |
| `char` | Character | 8 bits |
| `wchar_t` | Wide character | 16 bits |
| `char16_t` | Unicode character | 16 bits |
| `char32_t` | Unicode character | 32 bits |
| `short` | Short integer | 16 bits |
| `int` | Integer | 16 bits (`32` bits on a 32-bit machine) |
| `long` | Long integer | 32 bits |
| `long long` | Long integer | 64 bits (introduced in C++11) |
| `float` | Single-precision floating point | 6 significant digits |
| `double` | Double-precision floating point | 10 significant digits |
| `long double` | Extended-precision floating point | 10 significant digits |

### How to Choose a Type

- When you know a value can never be negative, use an unsigned type.
- Use `int` for integer arithmetic. In many systems `long` is the same size as `int`, while `short` is often too small. Use `long long` only when the value may exceed the range of `int`.
- Do not use `char` or `bool` in arithmetic expressions.
- Use `double` for floating-point calculations.

### Type Conversions

- Assigning a non-`bool` value to `bool`: if the initial value is `0`, the result is `false`; otherwise it is `true`.
- Assigning a `bool` value to a non-`bool` type: `false` becomes `0`, and `true` becomes `1`.

### Literal Constants

- A value such as `42` is called a **literal constant**.
	- Integer and floating-point literals
	- Character and string literals
		- Adjacent string literals are concatenated, inherited from C.
		- Character literal: single quotes, such as `'a'`
		- String literal: double quotes, such as `"Hello World"`
		- A string literal may be written across multiple lines by placing adjacent literals next to each other.
			```c++
			std::cout << "wow, a really, really long string"
									 "literal that spans two lines" << std::endl;
			```
	- Escape sequences such as `\n` and `\t`
	- Boolean literals: `true`, `false`
	- Pointer literal: `nullptr`

> A string literal is actually an array of constant characters terminated by `\0`, so its real length is one more than the visible content.

## Variables

A **variable** provides a **named** storage location that a program can use. In C++, the terms **variable** and **object** are often used interchangeably.

### Variable Definitions

- **Definition form**: a type specifier followed by a list of one or more variable names, for example `int sum = 0, value, units_sold = 0;`
- **Initialization** means an object is given a specific value when it is created.
	- **Initialization is not assignment.**
	- Initialization = create the variable + give it an initial value
	- Assignment = erase the current value + replace it with a new value
	- **List initialization** uses braces, for example `int units_sold{0};`
	- Default initialization: if no initial value is given, the object is default-initialized. **Built-in variables inside a function body are not automatically initialized.**
	- It is good practice to initialize every built-in variable.

### Variable Declaration vs Variable Definition

- To support separate compilation, C++ distinguishes between **declarations** and **definitions**. 
   - A **declaration** makes a name known to the program. 
   - A **definition** creates the associated entity.

- **`extern`** means the variable is defined somewhere else.
- Declaration without definition: add `extern` before the variable name, for example `extern int i;`
   -. If an initial value is provided, it becomes a definition: `extern double pi = 3.14;`
- A variable may be defined only once, but it may be declared many times. The definition appears in one file, and other files use declarations to refer to that variable.

- **Scope** determines where a name is visible.
	- Define a variable when you first need to use it.
	- Scopes can be nested.
	- When both a global and a local variable with the same name exist, you can use `::reused` to explicitly access the global `reused`.
	- Even so, avoid reusing the same name for a local variable when a global variable already exists.


#### Variable Naming Conventions

1. A name should reflect its actual meaning.
2. Variable names usually use lowercase letters.
3. User-defined class names usually begin with an uppercase letter, such as `Sales_item`.
4. If an identifier contains multiple words, separate them clearly, such as `student_loan` or `studentLoan`, not `studentloan`.

## Lvalues and Rvalues

- An **lvalue** can appear on either the left or the right side of an assignment, such as a variable.
- An **rvalue** can appear only on the right side of an assignment, such as a literal constant.

## Compound Types

### References

> In most cases, when we say reference, we mean lvalue reference.

- A **reference** is an alias for an object. A reference type refers to another type, for example `int &refVal = val;`.
- A reference must be initialized.
- A reference is **bound** to its initial value, not copied. Once defined, it cannot be rebound to another object.

### Pointers

> `int *p;` means a pointer to an `int` object.

- A pointer is a compound type that **points to** an object of another type.
- To define a pointer type: `int *ip1;`. Reading from right to left often helps: `ip1` is a pointer to `int`.
- A pointer stores the address of an object.
- To get an object's address: `int i = 42; int *p = &i;`. Here `&` is the address-of operator.
- The type of a pointer must match the type of the object it points to.
- A pointer can be in one of four states:
	- It points to an object.
	- It points to the next location past the end of an object.
	- It is a null pointer.
	- It is an invalid pointer.
	- > Any operation on an invalid pointer causes errors. The second and third states are valid, but dereferencing them is not allowed.
- To access the pointed-to object: `cout << *p;`. Here `*` is the dereference operator.
- A null pointer points to no object. Use `int *p = nullptr;` to create one.
- > Difference between pointers and references: a reference is not itself an object and cannot be rebound after definition; a pointer has no such restriction and behaves like an ordinary variable.
- > An assignment statement always changes the object on the **left-hand side**.
- A `void*` pointer can hold the address of **any** object. Because it has no type information, it can only represent raw memory and cannot directly access the stored object.
- Other pointer types must match the pointed-to object **exactly**.
- The result type of subtracting two pointers is `ptrdiff_t`.
- Recommendation: initialize all pointers.
- `int* p1, p2;` means `*` applies only to `p1`, so `p2` is still an `int`.

## The `const` Qualifier

- Motivation: sometimes we want to define values that must not be changed.

### Initialization and `const`

- A `const` object **must be initialized** and **cannot be changed**.
- By default, a `const` variable is not accessible from other files. If you need to access it elsewhere, add `extern` to its definition. To share the same `const` variable across multiple files, use `extern` on both the declaration and the definition.

### References to `const`

- A **reference to const** refers to a const object, for example `const int ival = 1; const int &refVal = ival;`. You may read through `refVal`, but you may not modify it.
- A **temporary** object is an unnamed object the compiler creates to hold the result of an expression.
- Binding a non-const reference to a temporary object is illegal.

### Pointers and `const`

- A **pointer to const** cannot be used to change the object it points to, for example `const double pi = 3.14; const double *cptr = &pi;`.
- A **const pointer** means the pointer itself is constant. The stored address cannot change, though the pointed-to object may still be modifiable if it is not const, for example `int i = 0; int *const ptr = &i;`.

### Top-level `const`

- **Top-level `const`** means the object itself is const, such as a pointer that cannot change.
- **Low-level `const`** means the pointed-to object is const. When copying, low-level const qualifications must match.

### `constexpr` and Constant Expressions

- A **constant expression** is an expression whose value does not change and can be evaluated at compile time.
- Since C++11, a variable may be declared `constexpr`, allowing the compiler to verify that its value is a constant expression.

## Dealing with Types

### Type Aliases

- Traditional alias: use `typedef` to define a synonym for a type, for example `typedef double wages;`
- New standard alias: alias declaration, for example `using SI = Sales_item;` (C++11)

```c++
// For compound types such as pointers, do not substitute mechanically.
typedef char *pstring;  // pstring is an alias for char*
const pstring cstr = 0; // constant pointer to char
// Rewriting it as const char *cstr = 0; would be incorrect,
// because that means pointer to const char.

// Helpful interpretation
// const pstring cstr = 0; becomes const (char *) cstr = 0;
// const char *cstr = 0; means (const char *) cstr = 0;
```

### The `auto` Type Specifier

- The `auto` type specifier lets the compiler **deduce the type automatically**.
- A single declaration statement can have only one base type, so when using `auto` to declare multiple variables, they must all deduce to the same type, including `&` and `*`. For example, `auto sz = 0, pi = 3.14;` is an error.
- `int i = 0, &r = i; auto a = r;` deduces `a` as `int`.
- `auto` ignores top-level `const`.
- `const int ci = 1; const auto f = ci;` deduces the underlying type as `int`; if you want the result itself to be const, you must write `const` explicitly.

### The `decltype` Type Specifier

- `decltype` deduces the type of a variable from the type of an expression.
- `decltype` selects and returns the **data type** of its operand.
- `decltype(f()) sum = x;` deduces `sum` as the return type of function `f`.
- `decltype` does not ignore top-level `const`.
- If you put a variable inside parentheses, the compiler treats it as an expression. For example, if `i` is an `int`, then `decltype((i))` yields `int&`.
- Assignment is a typical expression that yields a reference. If `i` is `int`, then the expression `i = x` has type `int&`.
- `decltype` was introduced in C++11.

## User-defined Data Structures

### `struct`

> Try not to define a class and its objects in the same statement, such as `struct Student{} xiaoming, xiaofang;`

- A class can begin with the keyword `struct`, followed by the class name and class body.
- Data members are declared inside the class body.
- In C++11, a data member may have an **in-class initializer**.

### Writing Your Own Header Files

- Header files usually contain entities that should be defined only once: classes, `const` variables, and `constexpr` variables.

Overview of the preprocessor:

- The **preprocessor** helps ensure that a header file can be included multiple times safely.
- When the preprocessor sees `#include`, it replaces that directive with the contents of the specified header file.
- A **header guard** depends on whether a preprocessor variable is defined or not defined.
	- `#ifdef` is true if the name has been defined.
	- `#ifndef` is true if the name has not been defined.
	- Header guard names should be unique and written in all uppercase letters. Make it a habit to add header guards whether or not you think the file will be included multiple times.

```c++
#ifndef SALES_DATA_H  // true if SALES_DATA_H has not been defined
#define SALES_DATA_H
struct Sales_data {
		...
};
#endif
```
